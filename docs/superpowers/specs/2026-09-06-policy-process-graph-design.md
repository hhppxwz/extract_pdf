# 报销、差旅、采购流程条款与图谱构建设计

## 阶段目标

首期不建设面向全部制度的泛化知识图谱。系统只处理报销、差旅、采购三类办事事项：先为每个已结构化条款保存可复核的流程判定，再只从判为流程的条款中抽取实体和关系。阶段验收以“流程条款分流合理、候选有原文证据、非流程语句不会进入图谱”为准，不以问答或跨制度检索为验收项。

## 判定层

每个条款都创建一条版本化判定记录，绝不删除源条款：

| 判定 | 含义 | 是否进入抽取 |
| --- | --- | --- |
| `process` | 与报销、差旅、采购有关，且包含申请、提交、审批、办理、报销、结算、支付等办事动作或其材料、时限、金额、部门条件 | 是 |
| `non_process` | 总则、目的、原则、解释权、发布施行、宣传要求，或不属于三类事项的内容 | 否 |
| `pending` | 事项相关但没有足够证据，或规则与模型意见冲突，需要人工确认 | 否 |

判定记录包含事项域、原文证据、理由、置信度、来源（规则或模型）和人工审核状态。`process` 的证据必须是原文的连续片段；没有可定位证据时降为 `pending`。不配置模型时，规则无法确定的条款同样保留为 `pending`，不猜测性纳入图谱。

## 事项范围与规则

- 报销：报销、费用报销、报账、发票、报销单、票据、结算等。
- 差旅：出差、差旅、交通费、住宿费、差旅费、行程等。
- 采购：采购、购置、采购申请、供应商、招标、询价、验收等。
- 正向流程信号：申请、提交、提供、报送、审批、审核、批准、办理、支付、结算、备案、验收，以及材料、部门、期限、金额、标准等伴随信息。
- 直接排除信号：总则、目的、原则、适用范围、职责概述、解释权、施行日期、监督宣传等，除非同一条款明确给出上述三类事项的可执行办事步骤。

规则只自动接纳同时具有事项信号和流程信号、且能截取原文证据的高置信条款；当前版本将其余相关条款直接保留为 `pending`，不以模型猜测替代人工确认。后续只有在完成这批抽检、得到稳定的错分样本后，才评估是否让模型复核 `pending` 条款；即使引入模型，缺少原文连续证据的结论仍必须保持 `pending`。

## 图谱层

图谱抽取运行必须关联一个流程判定运行，只读取 `process` 且审核状态为自动通过或人工通过的条款。原有实体类型保留并优先使用：事项、对象/人员、部门、材料、金额/标准、时限、审批动作；关系使用适用对象、办理部门、所需材料、金额标准、时限、审批要求等。每个实体和关系必须保留条款、页码和原文证据。

不改写原有通用抽取命令。新增“先分流、后抽取”的命令，避免旧运行的全量抽取结果被误认为流程图谱。

## 单人质检闭环

导出两张可在 Excel 回填的表：

1. `流程条款抽检.csv`：逐条显示原文、系统判定、事项域、证据、理由、置信度和人工列 `分流正确`、`正确判定`、`错分原因`、`备注`。
2. `流程图谱抽检.csv`：仅显示由流程条款产生的实体和关系候选，人工填写 `正确性`、`缺失内容`、`备注`。

报告同时显示流程／非流程／待确认数、已抽检数、分流正确率、错分原因，以及图谱实体关系正确率和遗漏数。先以 10 份制度试运行、修正规则和提示词，再扩大到 574 份；不以一次性全量导入代替抽检。

## 数据流

```text
PDF 结构化条款
  → 规则分流（必要时模型复核）
  → 流程判定运行 + 可回填抽检表
  → 仅 process + 已确认条款
  → 实体关系抽取运行 + 图谱抽检表
  → 质量报告
```

## 非目标

- 本阶段不做问答、向量召回、跨制度排序或法律效力裁判。
- 不把模型的解释当作事实；所有入图内容都需要可定位原文证据。
- 不删除非流程条款或覆盖原始制度、条款、既有抽取运行。
