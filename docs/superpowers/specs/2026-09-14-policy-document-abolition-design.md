# 制度文档废止关系设计

## 目标

先建立制度文档之间可回查、可审核的“废止”关系，不在本阶段建设完整制度族、条款沿革、历史时间检索、SHACL、多格式接入或图谱页面。

系统应能从明确表述中识别类似以下规则：

> 本办法自2016年1月1日起施行，《武汉大学财务管理办法》（武大[2000]25号）即废止。

并保存新制度、被废止制度、关系生效日期、原文证据、页码、置信度和人工审核结论。

## 范围

### 本期包含

- 从制度条款中识别“废止”“同时废止”“即废止”等明确废止表述；
- 在同一条款中识别“自 YYYY 年 M 月 D 日起施行”等日期；
- 抽取被废止制度的标题和可选文号；
- 保存已解析或尚未解析的废止关系；
- 以文号优先、规范化标题辅助的方式关联已入库目标制度；
- 对每条关系提供人工审核；
- 审核通过后，更新被废止制度的效力状态和失效日期；
- 在命令行提供候选关系的查看与审核入口。

### 本期不包含

- 自动认定“修订”“替代”“依据”“引用”等其他关系；
- 条款级新旧条款对应和文本差异；
- 完整制度族和多个正式版本的归并；
- `as_of` 历史时间检索；
- 从无明确原文依据的文件推断生效、失效日期；
- Word、网页、SHACL、在线图谱页面。

## 设计原则

- 证据优先：每个日期和关系都保留条款、页码和原文证据；
- 允许未知：无证据时保存 `unknown`，不猜测法律效力；
- 先候选后生效：抽取结果不会直接修改目标制度状态，只有人工审核通过后才更新；
- 关系生效时间使用左闭右开区间。若新办法在 `2016-01-01` 生效且同时废止旧办法，旧办法的 `effective_to` 写为 `2016-01-01`，表示其适用范围为 `[effective_from, effective_to)`；
- 标题相同不足以自动关联。文号完全匹配可以自动提出高置信候选；标题辅助匹配只能待人工确认。

## 数据模型

新增表 `policy_document_relations`：

| 字段 | 含义 |
| --- | --- |
| `relation_id` | 关系唯一标识 |
| `source_policy_id` | 发出废止声明的新制度 |
| `target_policy_id` | 被废止的已入库制度；暂未匹配时为空 |
| `target_title` | 从原文抽取的被废止制度标题 |
| `target_doc_number` | 从原文抽取的被废止制度文号，可为空 |
| `relation_type` | 当前固定为 `abolishes` |
| `effective_date` | 废止关系生效日；可为空 |
| `evidence_clause_id` | 证据所在条款 |
| `evidence_text` | 完整原文证据片段 |
| `page_start` | 证据起始页 |
| `page_end` | 证据结束页 |
| `confidence` | 规则抽取与匹配的综合置信度 |
| `review_status` | `pending`、`approved`、`rejected` |
| `reviewer` | 审核人 |
| `review_note` | 审核说明 |
| `created_at`、`updated_at` | 审计时间 |

现有 `policy_documents` 继续保存 `validity_status`、`effective_date`、`expiry_date`。审核通过的废止关系只允许把目标制度更新为：

```text
validity_status = invalid
expiry_date = relation.effective_date（仅当关系日期明确）
```

源制度不会因一条废止关系自动标记为 `current`；其效力仍须由自身明确证据或人工确认决定。

## 处理流程

```text
制度条款结构化完成
  → 对每条条款运行废止关系规则抽取
  → 提取新办法生效日期、目标标题、目标文号和证据
  → 查找目标制度：文号精确匹配 > 标题规范化候选 > 未解析
  → 写入 pending 废止关系
  → 人工审核通过/拒绝
  → 通过时更新目标制度的废止状态与失效日期
```

### 抽取规则

规则只接受同一条款内同时具备以下内容的候选：

1. 废止触发词：`废止`、`同时废止`、`即废止`；
2. 目标制度引用：优先 `《……》`，括号中可包含文号；
3. 连续原文证据覆盖触发词和目标引用。

生效日期从同一条款中的“自……起施行”“自……起执行”“自……起生效”抽取。未发现日期时关系仍可保存，但 `effective_date` 为空且置信度降低，审核界面必须提示日期待核验。

### 目标匹配

1. 标准化文号完全匹配：将关系绑定到唯一目标制度，关系保持待审核；
2. 文号不匹配或缺失时，以标准化标题精确匹配查找候选；若唯一候选，预填目标但保持待审核；
3. 多个候选或没有候选时，不绑定 `target_policy_id`，保留标题和文号等待后续解析或人工选择；
4. 不采用模糊文本相似度自动绑定目标制度。

## 审核与幂等性

- 相同源制度、目标文本、证据条款和关系类型的候选幂等更新，避免重复导入；
- 审核通过时再次检查目标制度存在；目标不存在则拒绝通过并提示先导入或手工选择目标；
- 关系被拒绝不修改任何制度状态；
- 若已批准关系的日期被人工修正，应同步更新目标制度失效日期；
- 同一目标制度出现多个已批准废止关系且日期不同，禁止静默覆盖，转为审核冲突。

## 接口与命令

新增最小命令行接口：

```powershell
# 为已结构化的批次抽取废止关系候选
python main.py --extract-policy-abolition-relations batch_xxx

# 查看某批次的候选及审核状态
python main.py --policy-abolition-relation-status batch_xxx

# 逐条审核候选；支持选择目标制度和修正日期
python main.py --review-policy-abolition-relations batch_xxx --reviewer 张三
```

本期不新增 HTTP API；先通过命令行和数据库审核闭环验证抽取质量。

## 错误处理

- 条款不存在或批次不存在：命令失败并说明对象不存在；
- 没有制度结构化结果：不创建候选，提示先完成 PDF 批处理；
- 被引用制度未导入：保留未解析候选，不视为抽取失败；
- 日期无法识别：保留关系，日期为空；
- 审核通过时目标制度不存在、多候选未选择或存在已批准日期冲突：拒绝写入状态更新，要求人工处理。

## 测试与验收

必须覆盖：

1. 从“自2016年1月1日起施行，……即废止”抽取日期、标题、文号和证据；
2. 缺少明确日期时仍保存待审核候选；
3. 文号优先于标题匹配；
4. 标题多候选时不自动绑定；
5. 审核通过更新目标制度为 `invalid`，并设置失效日期；
6. 审核拒绝不修改目标制度；
7. 重复运行不会重复创建候选；
8. 同一目标的已批准日期冲突会阻止静默覆盖；
9. CLI 命令可发现并验证参数组合。
