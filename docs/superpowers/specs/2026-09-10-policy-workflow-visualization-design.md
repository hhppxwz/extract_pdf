# 在线办事流程图谱可视化设计

## 目标

为已审核的办事流程图谱提供一个由 FastAPI 托管的交互页面。用户通过运行 ID 打开页面后，可以浏览节点和关系，按实体类型筛选，并查看每个节点或关系对应的制度条款证据。

本次不改变图谱抽取、人工审核、JSON 导出或数据库表结构。

## 范围

新增页面路由 `GET /policy-workflow-view/{run_id}`。页面在浏览器中请求既有的 `GET /policy-workflow-graph/{run_id}`，该接口仍是图谱数据的唯一来源。

页面包含：

- 顶部摘要：运行 ID、节点数和关系数；
- 图谱画布：节点按 `type` 分色、关系带方向和关系类型；
- 类型筛选：可单独显示或隐藏某类节点；
- 证据面板：点击节点或关系后展示制度名称、条款 ID、页码和原文证据；
- 状态反馈：空图、加载中和加载失败都显示中文提示。

## 架构与数据流

页面 HTML 由 FastAPI 路由返回。页面使用固定版本的 ECharts CDN 资源绘制图谱，再向同源的图谱 JSON 接口发起请求。

`workflow_graph.json` 与图谱 API 的数据格式保持不变：

- 节点使用 `id`、`type`、`name` 与 `citations`；
- 边使用 `id`、`source`、`target`、`type` 与 `citations`；
- 前端只读取这些字段，不产生或写回任何图谱事实。

页面优先根据有向关系计算从左到右的层级位置；如果存在环或没有可用层级，回退到力导向布局。这样流程可读性优先，同时不会因循环关系而丢失节点。

## 错误处理

页面请求返回 422 时显示后端给出的运行 ID 错误；网络错误、非 JSON 响应或未知 HTTP 错误显示可理解的中文提示。返回的节点和边为空时保留页面框架，并提示当前运行尚无已审核图谱内容。

## 测试与文档

新增路由测试，覆盖页面正常返回、运行 ID 被安全嵌入、数据接口 URL 正确生成等行为。保留已有图谱 API 测试。README 新增从运行 ID 打开在线图谱页面的命令与地址示例。

## 非目标

- 不新增前端构建工具、npm 依赖或数据库迁移；
- 不支持编辑节点、关系或人工审核结果；
- 不把仅含条款层级的批处理 JSON 误绘制成语义流程图。
